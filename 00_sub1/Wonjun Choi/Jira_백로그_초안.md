# Jira 백로그 초안

## Story와 Task 구분

Story는 사용자가 직접 느끼는 가치가 있는 기능입니다.

예: 사용자는 코어를 분리하면 별도 설정 없이 실외 모드로 바뀌길 원한다.

Task는 사용자가 직접 보지는 않지만 기능 구현을 위해 필요한 내부 작업입니다.

예: 결합 감지용 홀 센서를 테스트한다.

Subtask는 Story나 Task를 더 작게 쪼갠 실행 단위입니다.

## Epic 1. Detachable Pet Core

### [Story] 코어 분리 시 자동으로 포켓 모드 전환

사용자로서 코어를 몸체에서 분리하면 별도 설정 없이 포켓 모드로 전환하고 싶다. 그래야 외출할 때 자연스럽게 펫을 데리고 나간다는 느낌을 받을 수 있다.

Acceptance Criteria:

- 코어 분리 상태를 감지한다.
- 분리 후 2초 이내 화면이 실외 모드로 바뀐다.
- 바디는 주행을 멈추거나 대기 상태로 전환한다.
- 분리 과정에서 저장된 상태 데이터가 유실되지 않는다.

### [Task] 코어 보드와 센서 구성 선정

- ESP32-S3 또는 대체 보드를 비교한다.
- 디스플레이, 터치 센서, 진동 모터, BLE 가능 여부를 확인한다.
- 최소 배터리 용량과 예상 사용 시간을 계산한다.

### [Task] 코어-바디 결합 구조 설계

- 자석 정렬 구조를 설계한다.
- 실제 고정용 래치 구조를 설계한다.
- 반복 결합 테스트 기준을 정한다.

### [Subtask] 결합 감지 방식 비교

- 홀 센서 방식 테스트
- 포고핀 접점 방식 테스트
- 분리 감지 지연 시간 측정

## Epic 2. Indoor Autonomous Body

### [Story] 집에서 부르면 펫이 다가오기

사용자로서 집에서 펫을 부르면 내 근처로 와서 따라다니길 원한다. 그래야 단순 장난감이 아니라 실제 공간에 함께 있는 존재처럼 느껴진다.

Acceptance Criteria:

- 호출 명령을 받으면 이동을 시작한다.
- 사용자를 일정 거리 안에서 따라간다.
- 장애물을 감지하면 정지한다.
- 사용자를 놓치면 무리하게 이동하지 않고 정지한다.

### [Task] 2륜 차동 구동 바디 구현

- 모터 드라이버를 연결한다.
- 전진, 후진, 좌회전, 우회전 동작을 구현한다.
- 기본 속도 제한을 설정한다.

### [Task] 실내 사용자 추적 실험

- 카메라 기반 추적과 거리 센서 기반 추적 중 MVP 방식을 선택한다.
- 따라가기 목표 거리를 정한다.
- 추적 실패 시 정지 로직을 구현한다.

### [Task] 장애물 정지 로직 구현

- 초음파, ToF, 범퍼 중 사용할 센서를 선택한다.
- 일정 거리 이내 장애물 감지 시 모터를 정지한다.
- 정지 상태를 웹/앱에 표시한다.

## Epic 3. Outdoor Companion Mode

### [Story] 외출 중 코어 터치 반응

사용자로서 밖에서 코어를 만졌을 때 표정과 진동으로 반응하길 원한다. 그래야 밖에서도 펫과 함께 있다는 느낌을 받을 수 있다.

Acceptance Criteria:

- 터치를 감지한다.
- 터치 시 표정이 바뀐다.
- 짧은 진동 또는 LED 반응이 발생한다.
- 실외 모드에서는 바디 제어 명령을 보내지 않는다.

### [Task] 가방 클립형 외장 프로토타입 제작

- 목걸이형 대신 가방 클립형을 기본으로 설계한다.
- 흔들림과 탈착 편의성을 테스트한다.
- 코어 목표 무게를 100g 이하로 관리한다.

### [Task] PWA 또는 모바일 웹 연동

- BLE 또는 네트워크 연동 방식을 정한다.
- 걸음 수, 위치, 사진 메모 이벤트를 저장한다.
- 사용자가 위치 기록을 끌 수 있게 한다.

## Epic 4. Identity and Memory Continuity

### [Story] 귀가 후 외출 기억 동기화

사용자로서 외출 후 코어를 다시 결합하면 펫이 오늘의 외출을 기억하는 것처럼 반응하길 원한다. 그래야 실내와 실외 경험이 하나로 이어진다.

Acceptance Criteria:

- 외출 중 생성된 이벤트가 저장된다.
- 결합 후 이벤트가 바디 또는 백엔드로 동기화된다.
- 동기화 결과에 따라 표정이나 메시지가 달라진다.
- 동기화 실패 시 재시도 또는 오류 상태를 표시한다.

### [Task] 기억 이벤트 데이터 구조 설계

- 이벤트 타입을 정의한다.
- 예: WALK_COUNT, PLACE_VISIT, PHOTO_MEMORY, TOUCH
- 이벤트 저장 API를 만든다.

### [Task] 펫 상태 저장 API 구현

- 현재 모드, 배터리, 결합 상태를 저장한다.
- 프론트엔드에서 상태를 조회할 수 있게 한다.
- 코어와 바디의 상태 불일치 상황을 처리한다.

## Epic 5. Integration, Safety, Demo

### [Story] 사용자가 데이터 기록을 직접 제어

사용자로서 마이크와 위치 기록을 직접 켜고 끄고 삭제하고 싶다. 그래야 귀여운 펫로봇이라도 내 사생활을 침범하지 않는다고 느낄 수 있다.

Acceptance Criteria:

- 위치 기록 on/off가 가능하다.
- 저장된 기억 이벤트를 삭제할 수 있다.
- 마이크는 버튼 입력 기반으로만 동작한다.
- 개인정보 관련 상태가 화면에 명확히 표시된다.

### [Task] 통합 데모 시나리오 제작

- 집 안 따라가기 장면을 준비한다.
- 현관에서 코어 분리 장면을 준비한다.
- 외출 모드 터치 반응 장면을 준비한다.
- 귀가 후 기억 동기화 장면을 준비한다.

### [Task] 실패 상황 테스트

- 코어 분리 중 통신이 끊기는 상황
- 바디가 사용자를 놓치는 상황
- 장애물 앞에서 멈추는 상황
- 배터리가 부족한 상황

## 우선순위

| 우선순위 | 항목 |
| --- | --- |
| Must | 코어 결합/분리, 자동 모드 전환, 실내 따라가기, 장애물 정지, 실외 터치 반응, 기억 동기화 |
| Should | 이름 부르기/호출, 배터리 표시, 수동 기억 기록, 간단한 장소 메모 |
| Could | 성장 요소, 스킨 변경, 더 다양한 표정, 외출 장소별 성격 변화 |
| Won't | 실외 자율주행, 얼굴 인식, 의료 알림, 항상 켜진 마이크, 4족 보행 |

## Jira 생성 추천

처음에는 Epic 5개를 만들고, 각 Epic 아래에 Story를 먼저 생성합니다. 구현 준비가 필요한 항목은 Task로 만들고, 하루 안에 끝낼 수 있는 작업은 Subtask로 쪼개는 방식이 좋습니다.

6주 프로젝트에서는 Story를 너무 많이 만들기보다, 발표 데모 흐름에 직접 연결되는 Story를 우선 배치하는 것이 좋습니다.
